# BuildSolid Canonical Identity

> Canonical identity reference for BuildSolid. Use this document when naming, positioning, or describing the project in repository docs, handoffs, templates, skills, examples, changelogs, and future specs.

---

## 1. Canonical Definition

BuildSolid is a **free, open-source Markdown framework for planning, building, and verifying software with AI**.

BuildSolid gives AI coding agents and human builders structured guidance for turning product intent into durable project artifacts: founder intent, discovery, product thesis, MVP scope, UX direction, intelligence-layer design, architecture, specs, plans, tasks, implementation, verification, reviews, deployment planning, launch prep, and iteration.

BuildSolid is expressed as Markdown artifacts and agent skills. Markdown retains accepted intent and meaning while agents execute and verify scoped project work. Bounded optional local helpers assist readable procedures without creating a required runtime. The framework's form does not establish its effectiveness or imply a plan to build a platform around it.

BuildSolid is a personal learning project shared freely for others to use and adapt. The creator intends to keep it free and open source, with no paid offerings or current plans to commercialize it. Feature development is ongoing; no roadmap or delivery date is promised.

## 2. What BuildSolid Is

BuildSolid is:

- A Markdown framework for structuring AI-assisted software creation.
- Guidance that keeps product intent, AI behavior, specs, decisions, and review context explicit.
- A skill-first workflow for AI coding agents.
- A markdown-first artifact system for preserving state across sessions, tools, and agents.
- A structured path from an idea to artifacts for planning, implementation and review.

## 3. What BuildSolid Is Not

BuildSolid is not:

- An IDE.
- A web app.
- A deployment platform.
- A no-code app builder.
- A generic AI wrapper.
- A simple prompt pack.
- A vibe-coding tool.
- A replacement for tools like Cursor, Claude Code, Lovable, Base44, Bolt, Replit, GitHub, Supabase, or Vercel.

Those tools may be used around or alongside BuildSolid. BuildSolid provides guidance, artifacts, and an agent workflow; people and their chosen tools implement the software and verify the results.

## 4. Positioning Guardrails

Use **BuildSolid** as the canonical project name.

Use this one-line description when a short definition is needed:

> BuildSolid is a free, open-source Markdown framework for planning, building, and verifying software with AI.

When more detail is needed, say that BuildSolid helps AI agents and human builders document intent, specs, tasks, implementation, verification, reviews, deployment planning, launch prep, and iteration. These artifacts make decisions reviewable; they do not guarantee compliance, prevent all drift or establish production readiness.

Do not describe BuildSolid as a product surface, runtime platform, generated app, hosted service, or replacement for an AI coding environment. BuildSolid remains Markdown-first and skill-first.

## 5. Scope Boundary

This document establishes identity and positioning only. It does not authorize new product functionality, runtime behavior, tooling, deployment automation, or architecture changes.
