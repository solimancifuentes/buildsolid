# BuildSolid Canonical Identity

> Canonical identity reference for BuildSolid. Use this document when naming, positioning, or describing the project in repository docs, handoffs, templates, skills, examples, changelogs, and future specs.

---

## 1. Canonical Definition

BuildSolid is a **software factory framework and intelligence layer for building real software with AI**.

BuildSolid gives AI coding agents and human builders a shared operating system for turning product intent into durable project artifacts: founder intent, discovery, product thesis, MVP scope, UX direction, intelligence-layer design, architecture, specs, plans, tasks, reviews, deployment planning, launch prep, and iteration.

BuildSolid is intentionally expressed as Markdown artifacts and agent skills. The Markdown-first shape proves the workflow before any tooling is built around it.

## 2. What BuildSolid Is

BuildSolid is:

- A software factory framework for structuring AI-assisted software creation.
- An intelligence layer that keeps product intent, AI behavior, specs, decisions, and review context explicit.
- A skill-first workflow for AI coding agents.
- A markdown-first artifact system for preserving state across sessions, tools, and agents.
- A disciplined path from raw idea to production-ready MVP artifacts.

## 3. What BuildSolid Is Not

BuildSolid is not:

- An IDE.
- A web app.
- A deployment platform.
- A no-code app builder.
- A generic AI wrapper.
- A simple prompt pack.
- A vibe-coding tool.
- A replacement for tools like Cursor, Claude Code, Lovable, Base44, Bolt, Replit, GitHub, Supabase, or Vercel.

Those tools may be used around or alongside BuildSolid. BuildSolid provides the framework, intelligence layer, artifacts, and agent workflow that make the work coherent.

## 4. Positioning Guardrails

Use **BuildSolid** as the canonical project name.

Use this one-line description when a short definition is needed:

> BuildSolid is a software factory framework and intelligence layer for building real software with AI.

When more detail is needed, say that BuildSolid helps AI agents and human builders move from founder intent to specs, tasks, reviews, deployment planning, launch prep, and iteration without losing context or prematurely jumping into implementation.

Do not describe BuildSolid as a product surface, runtime platform, generated app, hosted service, or replacement for an AI coding environment. BuildSolid remains Markdown-first and skill-first.

## 5. Scope Boundary

This document establishes identity and positioning only. It does not authorize new product functionality, runtime behavior, tooling, deployment automation, or architecture changes.
